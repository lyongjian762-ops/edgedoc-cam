这份文档只记录后续方案，不代表这些阶段已经实施或获批。

## L05-B 入口与方案

- L05-A 的功能、正式基准和质量检查须先通过，项目负责人同意后再开始。
- PR #7 `3536ab7f22fa0db5e595532df2c1708afa511781`、PR #8 `f8049b9c29471416cc30ea6f7291f3b135a2c2d5` 和 PR #10 `63dce9762ccbacf874aa456e16c45f5b4c40497e` 在本规划创建时均是 Draft，不能视为 main 已有依赖。需审查并确认最终来源 SHA；若暂时无法合并，可提出从明确 SHA 建临时集成分支，记录来源，不自动合并这些 PR。
- L02 原版曾完成 300 帧短测，R1 修改后的真实相机回归尚未做。`write reg array error` 的候选 BSP 源码与当前 boot Image 未证实一致，故根因仍未知。采集回归需单独获批，不能拿既有实验代替。
- 数据路径：发现并核验实际节点和 NV12 布局 → DQBUF → 校验有效数据 → 复制到独立快照 → 尽快 QBUF → 容量为 1 的等待队列 → CPU 图像编码与 OCR Worker → 校验结果并记录。必须测试异常时归还 buffer 和停止流。
- 先通过受控数据验证实际 NV12 的 stride、平面与颜色转换，再核对编码后的模型输入；不预设 RGB/BGR 排列。禁止在采集线程做 OCR 或等待队列空位。
- 每个任务保留 ID 和 `QUEUED`、`RUNNING`、`SUCCEEDED`、`FAILED`、`TIMED_OUT`、`REJECTED` 状态。连接失败、请求超时及服务端状态不明分别记录；客户端超时不表示模型停止。
- 退出条件：获批真实拍摄无敏感信息的印刷文档，完成可追踪的板端 OCR 闭环并核对输出；采集 buffer 不被长时间用于推理。提交独立 Draft PR 和 L05B 实验记录。

## L05-C 入口与方案

- L05-B 闭环达到阶段门槛且负责人同意后实施。先用可控 Mock 验证 Busy、断连、超时、截断、失败后恢复和排空停止；确认错误不会伪装成成功。
- 串联任务 ID、图像身份、日志和结果；服务端状态不明时禁止无限重试和继续派发。对有限次数的重复任务记录进程是否存活、fd、内存和状态变化。
- 真机服务实验限定并发、次数和时间，逐项保留失败证据；原始私人图片、模型和凭据不入库。最终报告说明功能、延迟、质量、资源、异常、复现及限制，并提交独立 Draft PR。
